# 1.2.20-beta

The candied water buckets, properly this time.

The reason the last fix did not work: `FlowingFluidBlock#takeLiquid` does not return the fluid the
*liquid* is, it returns the fluid the **block** was built from - and AoA builds its fluid blocks from
the flowing fluid. So scooping a candied water source reports `aoa3:candied_water_flowing`, while the
bucket holds `aoa3:candied_water`. Comparing the two directly never matched, the mapping fell through
to `fluid.getBucket()`, and that is AoA's own bucket.

Fluids are now compared as sources: a flowing fluid is reduced to its source before matching, on both
sides. That also covers any other mod whose fluid block reports a flowing variant.

Two more things, because guessing twice was two times too many:

* If the source comparison still cannot place a fluid, the fill asks the fluid which bucket declares
  it and matches that bucket's fluid instead - a different signal, from the source side.
* If even that fails, one log line names the fluid that could not be matched, so a mismatch can be
  read off the log instead of guessed at.

The candied water bucket's pour now places the source state explicitly rather than whatever the
fluid field reported, so a bucket never spills a half-level flow.

The build now refuses a `BucketFamily` that does not reduce flowing fluids to sources, since that is
exactly what made the previous attempt silently fall back to AoA's bucket.
